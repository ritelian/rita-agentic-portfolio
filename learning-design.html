DESIGN METHODS

Make the intended learning visible

My course-design experience includes ADDIE, backward design, experiential learning and Bloom’s taxonomy — connecting learning objectives with practice and project-based assessment.

Questions that guide the design

  • What does the audience need to do, and what is getting in the way?
  • Which gaps require learning, and which require better tools or processes?
  • What should learners practise before doing the task independently?
  • What evidence would demonstrate successful performance?

The following 45-minute session is a fictional example created for this portfolio. It is not a delivered client programme.

Audience: team leads who are beginning to use generative AI for everyday workplace communication.

Session: Review before you share
StageLearner experienceEvidence
Frame / 5 minCompare a source note with a plausible but inaccurate summary.Names the risk of unsupported claims.
Model / 10 minObserve a worked example of claim-by-claim verification.Explains why a claim is supported or unsupported.
Practise / 20 minAnnotate and rewrite a second fictional summary.Removes unsupported claims and retains the source meaning.
Assess / 10 minSubmit a revision with a short justification.Meets the accuracy and reasoning criteria.

Feedback should explain the decision

“The note says a review happens next week; it does not confirm a launch. Keep the review date and remove the launch claim.” Specific feedback gives the learner a method they can reuse.

Evaluate beyond completion

Use the performance task to check immediate understanding. A proposed follow-up would ask learners to apply the same method to a fresh example, using the same criteria. Attendance and satisfaction alone would not demonstrate transfer.

03 / PYTHON LEARNING JOURNEY

Read. Try.
Explain. Transfer.

I developed end-to-end learning materials for a Python course, including practical coding activities and GitHub-managed resources. This small, newly written lab illustrates a progression from guided reading to independent adaptation.

Illustrative sample · Beginner level

Fictional completion data. Requires basic familiarity with variables, lists and dictionaries. No learner records or client code are included.

The learner’s task

Count completed learning activities in a small dataset, then adapt the programme to return the names of learners who still need to finish.

learners = [
    {"name": "Alex", "complete": True},
    {"name": "Sam", "complete": False},
    {"name": "Jo", "complete": True},
]

completed = 0
for learner in learners:
    if learner["complete"]:
        completed += 1

print(completed)  # Expected result: 2
  1. Read: predict the result and identify the condition.
  2. Try: run the code, change one completion value and predict again.
  3. Explain: describe what the loop and condition each contribute.
  4. Transfer: collect the names where completion is false. Check an empty dataset too.

Assess reasoning as well as output

A successful solution returns the correct names, handles an empty list and explains the selection condition. Feedback addresses misconceptions about filtering, rather than only whether the code runs.
