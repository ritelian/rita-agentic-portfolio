02 / THE PROBLEM

Most course production time
isn’t spent on design.

In my technical course work, a large share of production is coordination, preparation and checking.

Technical courses in AI and data demand hours of SME coordination, lab preparation, repository setup and slide-by-slide auditing. Much of that work is repetitive: checking the same standards, fixing the same errors, rebuilding the same structures for every module. That is time taken away from the decisions that actually shape how people learn.

03 / THE SYSTEM

Standards written once.
Applied everywhere.

I designed a layered instruction system that Claude Code reads before it touches any content. Each layer has one job.

course/INSTRUCTION ARCHITECTURE
CLAUDE.md
Global standards

Brand, language and design standards. Lean, always loaded.

skills/qa-rubric.md
Quality criteria

Pass/fail criteria for every slide.

skills/activity-patterns.md
Activity patterns

Established activity designs to replicate, not reinvent.

skills/content-depth-rubric.md
Content depth

Orient → Define → Explain → Apply, for every topic.

modules/brief-[n].md
Module-specific context

Learning objectives, competencies, SME requirements and known gaps.

Global rules stay small. Specialist knowledge loads only when needed. Module briefs carry what is unique. The result is a system that scales across modules without the instructions bloating.

Architecture overview; internal instruction files and course materials are not reproduced here.

04 / THE WORKFLOW

AI does the volume.
People keep the judgement.

  1. 01
    DEFINE / HUMAN

    Make the pedagogical decisions.

    I translate the competency map and SME feedback into standards, rubrics and a module brief. This is where the pedagogical decisions are made.

  2. 02
    CREATE / AI-ASSISTED

    Audit first. Then stop.

    Claude Code audits the existing materials against the brief and rubrics, then produces an audit report. It stops there. No changes are made without explicit approval.

    Human checkpoint / Approve or redirect the plan before execution
  3. 03
    REVIEW / HUMAN

    Approve, inspect and test.

    I approve or redirect the plan. Claude Code executes. I then verify the output visually and smoke-test every coding lab before anything is deployed to GitHub.

    Release checkpoint / Visual verification and coding-lab smoke tests
05 / WHY THE HUMAN MATTERS

The system learns from
what review catches.

15slides

A failure that became a rule.

On one module, a first AI pass left placeholder text repeated across 15 slides, along with duplicated content. Review caught it.

Instead of treating it as a one-off manual fix, I encoded the failure into a new rubric. Repeated placeholders and duplicated content became explicit reasons to reject a subsequent pass.

That is the point of the design: every human checkpoint improves the system, not just the current output.

Catch the failure→Update the rubric→Check the next pass

07 / WHAT I LEARNED

The real skill isn’t prompting.
It’s system design.

Time saved in production can disappear in token costs if the architecture is careless. A bloated instruction file, an undefined scope or the wrong model for the task will drain budget fast.

What works is lean context, specialised skills, model choice matched to complexity, and a human at every critical checkpoint.

AI used this way is a production system. The human in the loop is what makes it work.
