02 / THE PROBLEM

Repetitive production
takes attention from design.

Learning-content production involves coordination, preparation and checking as well as design.

Preparing learning materials can involve repeated checks, technical setup and structural revisions. Reusable standards help organise those tasks and preserve attention for the decisions that shape how people learn.

03 / THE SYSTEM

Standards written once.
Applied everywhere.

A layered instruction structure gives each type of guidance a clear purpose. The following is an illustrative architecture, not a client repository.

learning-example/INSTRUCTION ARCHITECTURE
CLAUDE.md
Global standards

Language and design standards. Keep this layer lean.

skills/qa-rubric.md
Quality criteria

Pass/fail criteria for draft materials.

skills/activity-patterns.md
Activity patterns

Established activity designs to replicate, not reinvent.

skills/content-depth-rubric.md
Content depth

Orient → Define → Explain → Apply, for every topic.

modules/brief-[n].md
Module-specific context

Learning objectives, prerequisites and constraints.

Global rules stay small. Specialist knowledge loads only when needed. Module briefs carry what is unique. The result is a system that scales across modules without the instructions bloating.

Architecture overview; internal instruction files and course materials are not reproduced here.

04 / THE WORKFLOW

AI does the volume.
People keep the judgement.

  1. 01
    DEFINE / HUMAN

    Make the pedagogical decisions.

    Define the audience, intended capability, review criteria and brief. Make the pedagogical decisions explicit before drafting.

  2. 02
    CREATE / AI-ASSISTED

    Audit first. Then stop.

    Ask Claude Code to assess draft materials against the brief and rubrics, then produce an audit report. Require explicit approval before making changes.

    Human checkpoint / Approve or redirect the plan before execution
  3. 03
    REVIEW / HUMAN

    Approve, inspect and test.

    Approve or redirect the plan before execution. Review the output visually, test any code examples and inspect changes in GitHub before release.

    Release checkpoint / Visual verification and coding-lab smoke tests
05 / WHY THE HUMAN MATTERS

The system learns from
what review catches.

When review identifies a recurring problem, turn it into an explicit criterion. For example, a general quality rubric can reject placeholder text, duplicated content or an activity that does not support its learning objective.

The reviewer improves both the material and the instructions used for future drafts.

Catch the failure→Update the rubric→Check the next pass
06 / QUALITY CRITERIA

Make the checks
visible.

Learning alignment

Check that the explanation, activity and assessment support the same objective.

Technical review

Run code examples, inspect outputs and check the instructions before release.

Content clarity

Look for unsupported claims, incomplete text and unnecessary repetition.

Traceable changes

Keep revisions reviewable and make the final human decision explicit.

07 / DESIGN PRINCIPLES

The real skill isn’t prompting.
It’s system design.

Time saved in production can disappear in token costs if the architecture is careless. A bloated instruction file, an undefined scope or the wrong model for the task will drain budget fast.

What works is lean context, specialised skills, model choice matched to complexity, and a human at every critical checkpoint.

AI used this way is a production system. The human in the loop is what makes it work.
